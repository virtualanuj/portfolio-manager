# Portfolio Manager Phase 1 (Local) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A fully working local deployment of the portfolio manager (Spring Boot API + Next.js UI + Postgres in Docker) covering every v1 requirement in `intent.md`, so it can be accepted before any cloud work.

**Architecture:** Monorepo (`/api`, `/web`). Pure-Java domain core (FIFO lots, valuation, allocation) with Spring Data JPA persistence and REST controllers around it. Next.js App Router UI talks only to its own `/api/*` route handler, which proxies to the API on 127.0.0.1. No auth in this phase (localhost-only).

**Tech Stack:** Java 21, Gradle Kotlin DSL, Spring Boot 3.x, Spring Data JPA, Flyway, Postgres 16 (Docker), JUnit 5 + AssertJ + Testcontainers + WireMock; Next.js (App Router) + TypeScript + Tailwind + Recharts + SWR + TanStack Table + react-hook-form + zod; Vitest; Playwright.

**Spec:** `docs/spec.md` (design) and `docs/intent.md` (requirements). Section numbers below (§) refer to `spec.md`.

## Global Constraints

- Money/quantities: `BigDecimal` in Java, `NUMERIC` in Postgres (quantity/price `NUMERIC(24,8)`, totals `NUMERIC(20,4)`), decimal **strings** in JSON. No floats anywhere, and no arithmetic on money in the browser.
- FIFO cost basis; splits n:m rescale open lots; SELL beyond holdings is a violation (never a short).
- Snapshot date computed in `app.timezone`, default `UTC`. One snapshot row per date (upsert).
- Refresh is on demand only (no scheduler), asynchronous (`POST /api/refresh` → `202`), single-flight.
- Prices: Yahoo (stocks/ETFs/funds, no fallback feed) and CoinGecko (crypto, demo key optional). Manual price wins for `MANUAL` instruments.
- Local profile binds `127.0.0.1` and startup **fails** if not loopback. No auth code in this phase.
- CSV import limit 2 MB / 5,000 rows, generic schema only (§8). Errors are RFC 7807 `problem+json`.
- No third-party analytics or CDN assets in the UI (fonts self-hosted via `next/font`), so the UI renders offline.
- Git: commit after every task **directly on `main`** (decision); commit messages end with the attribution line from the harness. First commit is the existing docs.
- Toolchain: JDK 21 is provided and managed by the user (not installed by this plan; `JAVA_HOME` must point at it). Node is pinned to 22 LTS via `web/.nvmrc` (`nvm install 22` is user-space and allowed).
- UI direction (decision): **dark-first trading cockpit**. Dark is the default theme, with a light theme available via toggle. Dense but legible layouts, monospace/tabular numerals, restrained accent, high-contrast gain/loss colors.

## Offline note

"Offline local mode" here means nothing depends on the cloud: the whole app, DB and UI run on this machine. **Price refresh needs internet** (Yahoo/CoinGecko). Offline, everything else works, and instruments set to `MANUAL` price keep valuing. Refresh failures degrade to stale badges, never errors (tested in Task 6).

## Review Focus

1. Sell exceeding holdings via edit/delete of an earlier buy → `422` naming the offending transaction (Task 3).
2. Instrument with no price at all → excluded from totals, counted as `unpriced`, dashboard still renders (Task 4).
3. Same-day buy and sell entered in either order → `seq` ordering decides; replay is deterministic (Task 1).
4. Double-click Refresh / two tabs → one run, second gets `409`, one snapshot row (Task 6).
5. CSV with BOM, quoted commas, CRLF endings, duplicate rows, or oversell across the file → correct row-level errors, nothing committed (Task 7).
6. Internet down during Refresh → `PARTIAL`/`FAILED` run, last prices kept, UI banner, no exception page (Task 6, Task 10).
7. Reverse split (1:10) and fractional crypto quantities (8 dp) keep exact basis (Task 1).

